# 开发者手册：配置项口径与跨模块链路说明

本手册面向开发者、运维人员及后续接手团队，说明前端、后端、算法之间串联的配置项口径。该文档作为三大模块开发资料的公共口径说明，重点覆盖字段映射、单位换算、包含关系和关键判断，避免不同模块对同一配置项理解不一致。

## 1. 模块边界

| 模块 | 目录 | 职责 |
| --- | --- | --- |
| 前端 | `packing_service_frontend` | 页面输入、Excel 解析、基础校验、部分直径/重量预计算、提交任务、展示结果 |
| 后端 | `packing_service` | 保存任务 JSON、调用 Python 服务、接收回调、WebSocket 推送、基础资料接口 |
| 算法 | `py3dbp` | 托盘装箱、悬空装箱、图片生成、Excel 输出、核心口径判断 |

## 3. 前端提交数据结构

两类任务提交给后端的外层结构基本一致：

```json
{
  "orderID": "订单号",
  "data": {
    "config": {},
    "tableData": []
  }
}
```

后端会将 `data` 序列化保存为源 JSON，并把同一份 JSON 传给 Python。

## 5. 前端预计算口径

### 5.1 直径

前端在导入或保存行数据时计算：

```text
diameter = sqrt(4 * real_height * (real_thickness + 0.7) / 3.14 + tubeApproximate)
```

托盘页面中纸管值来自前端保存的 `tube.value`；悬空算法中使用后端纸管数据 `tubeApproximate` 重新计算 `d`。两者业务含义一致，但字段名不完全一致。

### 5.2 重量

前端计算：

```text
weight_calc = real_height * real_thickness * width * density * number / 1000000000
```

若导入重量存在：

- 页面重量单位为 kg 时，先除以 1000 转为吨。
- 导入重量与计算重量差异小于等于 5% 时，保留导入重量。
- 否则使用计算重量。

提交给算法的 `weight` 通常按吨处理。

## 7. 托盘装箱高度口径

### 7.1 货物高度生成

`main.py` 中两处主要入口都有同样逻辑：

```text
foam_height = data['config']['froth_height'] * 10
item_height = int(item['width']) + foam_height
```

含义：

- 页面 `froth_height` 单位为 cm。
- 算法乘 10 后得到 mm。
- 页面货物 `width` 通常为 mm。
- 算法小托货物高度 = 膜卷宽度 + 泡沫高度。

结论：托盘装箱的小托高度包含泡沫高度。

### 7.2 托盘高度

托盘基础资料进入算法时：

```text
tray_height = palletHeight * 100
```

算法中一个托盘装载单元通常为：

```text
装载单元高度 = 托盘高度 + 货物高度
```

其中货物高度已包含泡沫。

## 8. 膜叠膜口径

算法位置：`main.py -> OverlapHandler.handle_overlap()`

入口参数：

```text
handle_overlap(
  tray_length,
  tray_width,
  tray_height,
  tray_weight,
  overlap_height,
  overlap_total_height,
  overlap_flag,
  foam_height
)
```

函数开头执行：

```text
foam_height /= 10
```

因为外部传入的泡沫高度此前为 mm，这里转回 cm 参与阈值判断。

### 8.1 单个膜叠膜最大高度

判断条件：

```text
now_tray.height - tray_height - foam_height <= overlap_height
```

字段含义：

- `now_tray.height`：当前小托总高度，包含托盘高度和泡沫后的货物高度。
- `tray_height`：托盘高度。
- `foam_height`：泡沫高度。
- `overlap_height`：前端 `single_max_height`。

结论：

- 判断阈值时扣除了托盘高度。
- 也扣除了泡沫高度。
- 所以 `single_max_height` 实际更接近“膜卷本体宽度/高度”口径，而不是实际占车高度。

### 8.2 总体膜叠膜最大高度

判断条件：

```text
i.height - tray_height + h_count - (count + 1) * foam_height <= overlap_total_height
```

其中：

- `h_count` 是已累计的去托盘高度。
- 去托盘高度本身包含泡沫。
- 判断时按层数扣除了泡沫。
- 多层叠膜不会重复计每层托盘高度。

最终生成叠膜单元：

```text
lwh = [tray_length, tray_width, tray_height + h_count]
```

结论：

- 最终实际装载高度包含泡沫。
- 最终实际装载高度包含一个托盘高度。
- 前端 `entire_max_height` 的阈值判断口径不含泡沫、不重复含托盘。

### 8.3 业务/开发建议

如果产品希望页面字段表达“实际占车高度上限”，当前算法需要调整，否则页面文案应明确：

- 单个膜叠膜最大高度：不含托盘、不含泡沫。
- 总体膜叠膜最大高度：不含泡沫，不重复计托盘。

## 9. 横放口径

算法位置：`main.py -> OptimizePacking.pack_lying_items()` 和 `pack_circles()`

关键逻辑：

```text
lying_box_height_list.append(max_height_list[i] - packed_item.height)
pack_circles(tray_width, lying_box_height_list[...] - tray_height, tray_length, ...)
```

代码注释说明 `lying_box_height_list` 中的高度“包含托盘”。调用 `pack_circles()` 前再减去 `tray_height`。

横放成功后生成：

```text
Item(..., [tray_length, tray_width, tray_height + lying_items_height], ...)
```

结论：

- 横放可用高度 = 剩余空间 - 托盘高度。
- 横放结果高度 = 托盘高度 + 横放货物占用高度。
- 若 `lying_tray_flag` 为 true，结果展示/装载中保留托盘概念；若 false，前端展示中部分逻辑会区别处理。

## 11. 悬空装箱尺寸口径

算法位置：`suspend_algo.py -> SuspendPack.__init__()`

### 11.1 膜卷直径

```text
d = sqrt(tubeApproximate + 4 * real_height * (real_thickness + 0.7) / 3.14)
```

注意：悬空算法会再次根据后端纸管数据计算直径，不完全依赖前端提交的 `diameter`。

### 11.2 装载单元平面尺寸

```text
width = ceil(d / 10 + baffle_extra)
length = ceil(float(item['width']) / 10 + 10)
```

这里变量名容易误解：

- 算法变量 `width` 是挡板面/装载单元短边，单位 cm。
- 页面货物 `width` 是膜卷宽度，通常 mm。
- `d / 10` 将直径从 mm 转为 cm。
- `baffle_extra` 直接加到挡板面。
- `length` 由页面货物宽度换算而来，再加固定 10 cm。

## 12. 悬空叠膜规则口径

### 12.1 `1托3卷/6卷/托`

```text
if width * 3 + tray_height <= bin_min_height:
    height = width * 3 + tray_height
    n = 3
elif width * 2 + tray_height <= bin_min_height:
    height = width * 2 + tray_height
    n = 2
else:
    height = width + tray_height
    n = 1
```

口径：

- 完整单元最多 3 卷。
- 只计 1 个木托/木架高度。
- 若高度不足，逐级降为 2 卷或 1 卷。

### 12.2 `悬空2+1/悬空4+2`

```text
if width * 3 + tray_height * 2 <= bin_min_height:
    height = width * 3 + tray_height * 2
    n = 3
    tray_number_in_whole_tray = 2
elif width * 2 + tray_height <= bin_min_height:
    height = width * 2 + tray_height
    n = 2
    tray_number_in_whole_tray = 1
else:
    height = width + tray_height
    n = 1
    tray_number_in_whole_tray = 1
```

口径：

- 3 卷场景计 2 个木托/木架高度。
- 2 卷、1 卷场景计 1 个木托/木架高度。

### 12.3 `悬空1+1/悬空2+2`

```text
if width * 2 + tray_height * 2 <= bin_min_height:
    height = width * 2 + tray_height * 2
    n = 2
    tray_number_in_whole_tray = 2
else:
    height = width + tray_height
    n = 1
    tray_number_in_whole_tray = 1
```

口径：

- 2 卷场景计 2 个木托/木架高度。
- 1 卷场景计 1 个木托/木架高度。

## 13. 悬空膜卷宽度阈值

关键逻辑：

```text
single_width = width
if item['width'] <= overlap_width:
    n *= 2
    width *= 2
```

结论：

- 判断使用的是页面货物 `width`，不是算法变量 `width`。
- 满足阈值时，单元卷数 `n` 翻倍。
- 同时，装载单元宽度也翻倍。
- `single_width` 保留翻倍前的挡板面尺寸，用于后续挡板规格和余数处理。

## 14. 悬空泡沫高度

悬空前端没有 `froth_height` 配置，`suspend_algo.py` 也没有读取泡沫高度。

结论：

- 悬空装箱不包含泡沫高度。
- 如果业务要求悬空也考虑泡沫，需要新增前端配置、后端透传、算法高度公式和辅材口径。

## 15. 后端透传与转换点

### 15.1 托盘装箱后端

`PalletPackingController` 主要做：

- 校验请求中是否有 `data`。
- 保存源 JSON。
- 创建任务。
- 调 Python。
- 接收 Python 回调并推送 WebSocket。

它基本不改写 `config` 和 `tableData`。

### 15.2 悬空装箱后端

`SuspendController.computerFirst()` 额外处理 `recDate`：

- 如果前端日期是 UTC 格式并以 `Z` 结尾，后端转为 Asia/Shanghai 时间字符串。
- 其他字段基本透传。
