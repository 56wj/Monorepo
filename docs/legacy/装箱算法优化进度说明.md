# 装箱算法优化进度说明

## 一、悬空装箱“回”字形问题

### 1. 问题描述

悬空装箱在使用 MaxRects 系列算法计算时，部分结果会出现外围被货物占据、中间留有封闭空白区域的“回”字形布局。该结果虽然满足二维矩形不重叠约束，但不符合现场实际装载要求。

### 2. 处理方案

目前已在悬空装箱结果生成后增加封闭空洞检测：

- 将货物边界离散为二维网格；
- 从车辆边界对空白区域进行连通性搜索；
- 无法与车辆边界连通的空白区域判定为封闭空洞；
- 对多个 MaxRects 候选结果进行统一检查；
- 在剩余货物数量接近时，优先选择不存在封闭空洞的方案；
- 保留旧选择逻辑作为回退模式。

### 3. 当前状态

**该问题已解决。**

封闭空洞检测和候选方案筛选逻辑已经完成，典型“回”字形和开放缺口场景验证通过。当前结果会优先规避中间封闭空白区域。

## 二、托盘装箱膜叠膜问题

### 1. 问题描述

托盘装箱开启膜叠膜后，现有算法会优先把同规格、满足高度限制的托盘进行合并。该策略能够减少托盘数量，但部分订单中会产生过多高托盘，使车辆内部剩余高度和零散托盘位难以利用。

最终表现为：局部看膜叠膜数量增加、托盘数量减少，但从整车装载结果看，部分小体积托盘无法继续组合，整体装入数量或空间利用率没有改善。

主要涉及以下代码：

```text
OverlapHandler.handle_overlap()
OptimizePacking.optimize_packing()
PackAll.pack_all()
```

## 三、第一版优化方案：调整现有贪心和拆叠策略

### 1. 方案内容

第一版方案保留现有算法框架，主要进行以下调整：

1. 调整同规格托盘的高度排序规则；
2. 限制单个托盘连续膜叠膜的层数；
3. 在车辆装不下时，优先拆解高度较高的膜叠膜托盘；
4. 根据拆解前后的超高量，决定继续拆解还是恢复上一轮结果；
5. 尝试通过高度差和剩余托盘数修正原有贪心评分。

该方案改动范围较小，可以继续复用现有 `OverlapHandler` 和 `OptimizePacking` 流程。

### 2. 验证结果

**第一版方案验证未达到预期，暂不采用。**

主要问题如下：

- 算法仍然只生成一条贪心路径，初始膜叠膜组合一旦选定，后续调整空间有限；
- 计算结果对货物排序比较敏感，改变输入顺序可能得到不同组合；
- 先膜叠膜、装不下再拆解属于事后修正，无法提前判断某次叠层是否会影响后续整车装载；
- 限制叠层虽然能减少高托盘，但部分订单又会增加托盘占用；
- 不同订单需要不同参数，固定层数和固定高度惩罚难以稳定覆盖全部场景。

## 四、第二版优化方案：寻找新的全局组合算法

### 1. 调整方向

第二版方案不再直接生成唯一的膜叠膜结果，而是先生成多组候选方案，再结合车辆装载结果进行全局比较。

候选方案包括：

- 完全不进行膜叠膜；
- 只进行两层膜叠膜；
- 在高度和重量允许时生成多层膜叠膜；
- 对部分规格保留矮托盘，用于填充车辆剩余空间；
- 对已经形成的膜叠膜托盘生成可拆分候选。

每组候选最终都进入车辆装载计算，再根据整体结果选择最优方案。

### 2. 新算法候选

目前计划重点评估以下算法：

#### 2.1 Beam Search

每轮只保留评分最好的若干个膜叠膜组合，在控制计算量的同时扩大搜索范围。

#### 2.2 分支限界与状态剪枝

对明显超高、超重或不可能优于当前最优结果的组合提前停止计算，并对相同规格、相同层数的重复状态进行合并。

#### 2.3 禁忌搜索或模拟退火

从一个可行装载方案出发，通过拆分、合并、交换托盘等操作持续寻找更优组合，用于对 Beam Search 结果进行二次局部优化。

#### 2.4 约束规划模型

将膜叠膜层数、车辆托盘位、高度和载重统一建模，评估使用 OR-Tools CP-SAT 求解中小规模订单的可行性。


### 5. 当前状态

第二版方案目前处于新算法选型和验证样例整理阶段。目前在测试 Beam Search 最小原型，通过实际订单确认全局候选搜索是否能够稳定改善装入数量和车辆空间利用率，再确定最终算法路线。
